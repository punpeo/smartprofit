# 盈析 · 电商利润经营分析系统 — 产品优化方案

**版本**: v2.0  
**角色**: B 端电商利润经营分析后台  
**用户**: 电商运营、财务、店铺负责人  
**核心场景**: 数据看盘 → 店铺管理 → 文件导入对账 → 利润核算

---

## 一、整体架构优化思路

### 当前问题诊断

| 页面 | 问题 |
|------|------|
| 首页 | 纯展示，无数据入口，用户进来后必须二次点击才能进入工作流 |
| 经营总览 | 时间筛选与数据联动已实现，但缺少「数据更新时间」提示和「导入入口」 |
| 店铺详情 | 新增/编辑功能完善，但缺少导入引流，用户不知道数据从哪来 |
| 后台管理 | 四大模块堆砌在侧栏，缺少引导；文件导入分散在各自模块内，用户需要多次切换 |

### 优化原则

```
首页：品牌展示 + 快速入口（3 秒到达核心功能）
经营总览：一眼看全局 + 异常预警 + 数据新鲜度提示
店铺详情：深入单个店铺 + 无缝导入引流
后台管理：工作台思维，高频操作前置，低频操作折叠
```

### 页面分层逻辑

```
首页（品牌层）
  ↓ 进入系统
经营总览（监控层）← 数据新鲜度提示 → 提示去导入
  ↓ 点击店铺
店铺详情（分析层）← 导入引流入口
  ↓ 管理
后台管理（配置层）← 文件导入 + 基础数据管理
```

## 三、文件导入功能完整规划

### 3.1 放置位置推荐

| 位置 | 入口 | 适用场景 | 优先级 |
|------|------|---------|--------|
| **后台管理 → 文件导入中心** | 侧栏独立模块 | 集中管理，批量导入，查看导入历史 | P0 |
| 经营总览 → 右上角按钮 | 悬浮「导入数据」 | 看数据时发现缺失，快速补导 | P0 |
| 店铺详情 → 批量导入下拉 | 按钮下拉菜单 | 针对单个店铺补充数据 | P0 |
| 首页 → Hero CTA | 「导入数据」按钮 | 首次使用快速上手 | P2 |

**选址理由**: 多入口兼容不同用户心智——运营看到数据缺失时从看板直接导，财务从后台集中管理，店长从店铺页针对性导入。

## 四、配套联动逻辑

```
文件导入完成
  │
  ├─→ daily_sales_logs 写入 → 触发器 → daily_profit_logs.sales 更新
  ├─→ daily_aftersale_logs 写入 → SaveSKU拉取 → profit.return_count 更新
  ├─→ daily_promotion_logs 写入 → 触发器 → profit.promotion_* 更新
  └─→ daily_fill_order_logs 写入 → 触发器 → profit.fill_order_* 更新
       │
       ▼
  前端页面自动刷新：
  ├─ 经营总览: KPI卡片 + 店铺排名表 重新拉取API
  ├─ 店铺详情: 汇总卡片 + SKU列表 自动重载
  └─ 每日记录: 数据列表 自动刷新
```
